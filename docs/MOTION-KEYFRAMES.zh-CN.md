# 关键姿势工具的技术约定

项目动作生产规则由 gameart 仓库的 `Docs/Workflows/KeyframeMotion.md` 统一维护，包括关键姿势来源、短长动作、节奏、共享工作流、空间对齐、连续性和可用动作验收。本页只维护本工具的接口与能力边界，不复制项目规则。命令见 [关键姿势工具](../tools/keyframe_motion/README.zh-CN.md)。

当前本机接入（2026-10-28）：项目规范位于 `D:\CurrentWork\gameart`，工具位于 `F:\video2rig`。这些是工作目录，不写入可移交资产的内部依赖；换机器时按实际 checkout 定位。

## 共享图与动作数据

`workflows/keyframes/Action.workflow.json` 与 `Action.api.json` 是同一节点图的界面和 API 格式。`prepare` 为动作准备输入、起始骨架、提示词与参数；`request` 按指定动作填入共享 API 图，不提交队列。新增动作不输出节点图副本。

动作包的 `parameters.json` 与 `prompt.txt` 是当前生成输入，`action.json` 保留准备时的动作合同。`prepared.json` 记录角色及首尾姿势身份和共享模板路径；实际帧数与时间由当前参数推导，避免修改时长后读取过期派生值。正式生成时保存实际完整请求及结果关联，不以之后可能变化的模板重建历史执行事实。

界面直接操作同一工作流时，对照 `request` 输出填写首尾图、完整提示词、帧数、尺寸、步数、种子与输出前缀。安装目录只有一个 `Keyframes_Action.json`；历史八秒图保留作对照，不作为本入口。

## 帧数与时间

当前 H3 接口使用 24 fps、`17k+5` 帧。满足项目短长动作范围的短片为 39/56 帧，长片为 73/90/107 帧；工具在所属范围内选择最接近目标时长的合法值。实际时长分别约为 1.63、2.33、3.04、3.75、4.46 秒，不把 124 帧称为 5 秒。

视频文件时长为帧数除以帧率，尾帧时间为 `(帧数−1)/帧率`；关键姿势在时间线上的位置以帧号为准。`request` 自动将实际片长与尾帧时间加到提示词中。提示词正文的动作节奏由制作者维护，不因数字换算自动重写。

模型或接口变更后，按实际节点合同调整量化方法并检查界面/API 配套；不把本页的参数当成其他模型的默认值。

## 当前能力边界

- 姿势、角色和渲染文件通过指纹配套；相机复用已建立的标定。换首姿势时准备对应 `rig.json`，不能仅替换 PNG。
- 当前视频入口只接首尾图。保存的中间关键图和边界附近帧不被 H3 消费，不能声称已约束中间姿态或速度。
- `train/evaluate/read/fit` 默认仅预览任务，显式 `--execute` 才执行单项计算；不自动串跑。角色级 reader 共享复用，读取时检查完整标签定义；无配套 reader 时不能进入旧跟踪路线。固定相机、24fps、米制求解和固定肘膝标定由关键姿势适配入口消费，不能用原版 `run` 替代。具体参数与限制见工具说明。
- 原骨架回传只支持已记录的同名同层级骨架转换，具体限制和矩阵约定见工具说明；不支持任意角色重定向，不丢弃未支持的道具轨道。
- `join` 检查共享边界合同；给出两份真实拟合 NPZ 才计算边界位置、姿态及相邻帧速度。它不自动对齐根位置、不修脚滑，也不判断完整动作是否自然。
- 复用现有依赖；本工具不修改核心 `video2rig/`、`blender/` 或第三方代码，不提供界面、不安装模型、不自动生成、训练或导入 Unity。拟合适配使用实例扩展和已有计算入口，仍须真实动态验收；当前样例的实际状态以工作包记录为准。
